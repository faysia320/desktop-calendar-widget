# Desktop Calendar Widget (PoC)

Google·Outlook 일정을 바탕화면에 표시하는 Windows 위젯의 기술 검증용 앱입니다.

## 실행

```powershell
pnpm install
pnpm tauri dev
```

`Ctrl+Alt+K`를 누르면 위젯이 맨 앞으로 나오고, 다시 누르면 바탕화면 고정 상태로 돌아갑니다.

실행 중에는 작업 표시줄 트레이에 아이콘이 있습니다. 왼쪽 클릭은 `Ctrl+Alt+K`와 같고, 오른쪽 클릭 메뉴에서 위젯을 불러오거나 종료할 수 있습니다.

일정에 마우스를 올리면 시간과 장소를 툴팁으로 보여 줍니다. 수정 가능한 Google 일정은 클릭하여 편집하고, 빈 날짜 칸을 더블클릭하거나 달력 상단의 `+` 버튼으로 추가합니다. `+N개`를 누르면 숨겨진 일정도 팝오버에서 확인하고 편집할 수 있습니다. Outlook 일정은 기존과 같이 읽기 전용입니다.

달력과 회의실 시간표는 상단에, Teams 채널 영역은 앱 하단 전체 너비에 표시합니다. GeekNews는 채널 영역의 첫 번째 고정 탭이며 닫을 수 없습니다. Teams 로그인 없이도 소식을 읽을 수 있고, 30분 자동 갱신과 수동 새로고침을 지원합니다. 글을 누르면 기본 브라우저로 열립니다. 탭을 바꿔도 뉴스 목록과 스크롤 위치를 유지하며 매번 다시 다운로드하지 않습니다. GeekNews를 선택한 상태도 재실행 후 복원됩니다.

모니터 연결이나 배치가 바뀌면 위젯은 보이는 모니터로 옮겨 가고, 원래 모니터가 돌아오면 그 자리로 돌아갑니다.

## 설치와 자동 실행

```powershell
pnpm build:app
# 기존 D: 드라이브 캐시를 재사용할 때
pnpm build:app -TargetDirectory D:\cargo-target
```

빌드한 실행 파일을 `%LOCALAPPDATA%\Programs\desktop-calendar-widget`에 복사해 실행합니다. 자동 실행에서는 작업 폴더가 달라지므로 `.env.local`을 `%APPDATA%\com.rocket.desktopcalendarwidget`에도 복사합니다. 위젯의 "Windows 시작 시 실행"을 켜면 실행 중인 파일의 경로가 등록되며, 개발 빌드에서는 등록되지 않습니다.

## 반복 빌드 최적화

`pnpm build:app`은 프런트엔드를 빌드한 뒤 Windows 실행 파일 하나만 만듭니다. 기본 캐시는 `src-tauri/target`이며, `-TargetDirectory`로 다른 경로를 고정할 수 있습니다. 다른 프로젝트에서 설정한 `CARGO_TARGET_DIR`은 이 명령에 영향을 주지 않습니다. 기존 캐시를 사용하려면 위 예시처럼 `D:\cargo-target`를 계속 지정하세요. 의존성 버전은 `--locked`로 고정합니다.

기본 release는 `opt-level=2`, `codegen-units=16`, `lto=false`, `incremental=true`를 사용합니다. Windows 실행 파일에서 사용하지 않는 staticlib/cdylib 출력은 제거했습니다. 프런트엔드 파일을 포함하는 `generate_context!()`는 작은 `main.rs`에 두고, 네이티브 백엔드는 별도 rlib로 유지하므로 UI 수정 때 백엔드 전체를 다시 컴파일하지 않습니다. 화면 작업 중에는 `pnpm tauri dev`의 즉시 갱신을 쓰고, 설치할 때 실행 파일을 빌드합니다.

이 환경에서 실제 UI 변경 후 측정한 네이티브 빌드는 기존 약 6분 40초에서 14~32초로 줄었고, 프런트엔드를 포함한 전체 빌드는 19~45초였습니다(2026-11-09). 아무 변경이 없는 빌드가 아니라 CSS 수정 및 자산 재생성 후의 측정입니다. 환경 부하와 변경 범위에 따라 달라집니다.

최초 설정 변경·의존성 변경 시에는 캐시 재생성이 필요하며 반복 빌드보다 오래 걸립니다. `scripts/build-app.ps1`은 프런트엔드/네이티브/전체 시간을 측정해 캐시 폴더의 `widget-build-times.json`에 기록하고, Cargo 상세 보고서는 `cargo-timings/cargo-timing.html`에 저장합니다. 빌드 결과 실행 파일 경로도 출력합니다.

더 작은 배포 파일을 우선할 경우 `pnpm build:app -Distribution`을 사용합니다. 이 별도 프로필은 Thin LTO와 더 강한 최적화를 사용하므로 일상적인 업데이트보다 느릴 수 있습니다. 일반 `pnpm tauri build --no-bundle`도 개선된 기본 release 설정을 사용하지만, 프로젝트 캐시 고정과 시간 측정은 `build:app` 명령을 사용해야 합니다. 이 프로젝트는 Windows 데스크톱 대상이며 모바일 라이브러리 출력을 만들지 않습니다.

## 캘린더 연동 설정

`.env.example`을 `.env.local`로 복사한 뒤 아래에서 발급한 값을 입력합니다.

### Google

1. Google Cloud Console에서 프로젝트를 만들고 Google Calendar API를 사용 설정합니다.
2. OAuth 동의 화면에 `calendar.events` 범위를 추가합니다.
3. 유형이 "데스크톱 앱"인 OAuth 클라이언트를 만들고 ID를 `GOOGLE_CLIENT_ID`, 보안 비밀을 `GOOGLE_CLIENT_SECRET`에 입력합니다.

게시 상태가 `Testing`이면 로그인이 7일 뒤 만료됩니다. `In production`으로 게시하면 검증 전에는 로그인할 때 "확인되지 않은 앱" 경고가 표시됩니다.

### Microsoft

1. Microsoft Entra 관리 센터의 앱 등록에서 새 앱을 만듭니다. 계정 유형은 단일 테넌트로 둡니다.
2. "모바일 및 데스크톱 애플리케이션" 플랫폼에 리디렉션 URI `http://localhost`를 추가합니다.
3. API 사용 권한에 Microsoft Graph의 위임된 권한 `Calendars.Read`와 `Calendars.Read.Shared`를 추가하고 조직 정책에 따라 동의합니다.
4. 애플리케이션 ID를 `MICROSOFT_CLIENT_ID`, 디렉터리(테넌트) ID를 `MICROSOFT_TENANT_ID`에 입력합니다.
5. 회의실 예약도 보려면 회의실 메일 주소를 쉼표로 구분해 `MICROSOFT_ROOMS`에 입력합니다. 입력한 순서대로 `회의실 1`, `회의실 2`로 표시합니다.

### Teams 채널

1. 위 Microsoft 앱 등록에 Microsoft Graph **위임된 권한** `ChannelMessage.Read.All`, `ChannelMessage.Send`, `User.Read`, `ChannelMember.Read.All`를 추가합니다. 채널 대화·멤버 읽기 권한은 관리자 동의가 필요합니다.
2. 위젯의 Teams 패널에서 **연결**을 눌러 회사 계정으로 로그인합니다. Outlook과 같은 앱 등록을 사용하지만 Teams 인증 정보는 Windows 자격 증명 저장소에 따로 저장하므로 일정 연결에 영향을 주지 않습니다.
3. Teams 채널의 `··· → 채널 링크 복사`로 링크를 복사한 뒤 패널의 `+`에 붙여 넣습니다. 탭 이름을 따로 지정할 수 있고, 같은 채널을 다시 추가하면 기존 탭을 선택하고 이름을 갱신합니다.

채널 탭과 마지막 선택은 `%APPDATA%\com.rocket.desktopcalendarwidget\teams-channels.json`에 즉시 저장되어 재실행 후에도 유지됩니다. 이전 웹뷰 저장소의 목록은 최초 실행 시 자동으로 옮기며, 불러오기 실패 시 빈 목록으로 덮어쓰지 않습니다. 저장에 실패하면 변경 전 목록을 유지하고 오류를 표시합니다. 채널 탭을 드래그하면 순서를 바꾸고 즉시 저장합니다. 탭이 많으면 가장자리에서 자동으로 가로 스크롤합니다. GeekNews는 첫 번째 고정 탭입니다. 채널 탭을 우클릭한 뒤 **채널 닫기**를 선택하면 위젯의 탭만 닫으며 Teams 채널을 삭제하지 않습니다. 키보드에서는 Shift+F10으로 같은 메뉴를 열고 Esc로 닫을 수 있습니다. 현재 탭의 대화를 1분마다 갱신하고, **이전 대화 더 보기**로 이전 페이지를 불러옵니다. 대화는 오래된 순서부터 아래로 이어지며 처음 열면 최신 메시지를 보여 줍니다. 위쪽 대화를 읽는 중에는 자동 갱신되어도 읽던 위치를 유지합니다. 오류 시 점진적으로 재시도 간격을 늘리고, 요청 제한 응답의 대기 시간을 따릅니다. **다시 시도**로 수동 갱신하거나 인증 오류일 때 **Teams 다시 연결**을 사용합니다.

본문의 HTML을 직접 삽입하지 않고 허용한 React 요소로 다시 구성합니다. 굵게·기울임·밑줄·취소선·제목·문단·목록·인용·코드·표·셀 병합·멘션을 유지합니다. 표는 셀 경계를 표시하며 좁은 화면에서는 표 안에서 가로로 스크롤합니다. 링크 제목과 줄바꿈을 유지하고, 일반 텍스트의 URL도 자동으로 연결합니다. 링크를 누르면 기본 브라우저로 열고 긴 주소는 줄바꿈합니다. 메시지 아래에 이모지별 반응 수와 댓글 수를 표시합니다. 반응을 누르면 추가되고, 내가 누른 반응을 다시 누르면 취소됩니다. `☺ +`에서 다른 이모지를 선택할 수 있습니다. 본인 반응 구분에는 `User.Read` 권한을 사용합니다. 사용자 지정 반응은 Teams에서 관리합니다. **댓글 N개 · 보기 / 작성**에서 스레드를 확인합니다. 메시지 입력창은 한 줄 높이로 시작하고 내용의 줄바꿈과 자동 줄바꿈에 맞춰 높이가 자동으로 늘어나거나 줄어듭니다. 수동 크기 조절은 없으며, 최대 144px 이후에는 입력창 내부를 스크롤합니다. 내용 삭제 또는 전송 완료 시 한 줄 높이로 돌아옵니다. **Enter는 전송, Shift+Enter는 줄바꿈**입니다. 한글 조합을 확정하는 Enter는 전송하지 않습니다. 입력창은 대화 목록과 분리해 처리하고 한글 조합 중 값을 다시 설정하거나 포커스를 반복 이동하지 않습니다. Teams 인증이 필요한 본문 이미지·첨부 파일 및 지원하지 않는 카드는 **Teams에서 열기**로 확인합니다. 전송 오류 시 초안을 유지하고 자동 재전송하지 않습니다. 메시지 본문과 작성 중인 초안은 디스크에 저장하지 않습니다.

`@` 뒤에 이름이나 이메일을 입력하면 현재 채널의 멤버를 검색합니다. 방향키와 Enter 또는 클릭으로 선택하고, 선택한 뒤 Enter를 다시 누르면 전송합니다. Escape로 선택창을 닫습니다. 선택한 멘션은 이름과 사용자 ID를 함께 전송하므로 Teams의 실제 사용자 멘션으로 처리됩니다. 선택한 이름을 수정하면 해당 멘션은 일반 텍스트로 바뀝니다. 멤버 조회 권한을 추가한 기존 사용자는 관리자 동의 후 Teams를 다시 연결해야 할 수 있습니다. 채널·팀 전체 또는 태그 멘션은 지원하지 않습니다.

채널 링크나 메시지 입력란을 눌러도 바탕화면 고정 상태를 유지하며 입력란에만 키보드 포커스를 줍니다. 맨 앞으로 불러오기와 바탕화면 고정 전환은 `Ctrl+Alt+K` 또는 트레이 메뉴로 조작합니다. 다른 조직의 채널은 앱에 설정된 테넌트와 로그인 계정의 접근 권한에 따라 열리지 않을 수 있습니다.

메시지에는 배경 버블을 표시하고, 링크 아래에 제목·설명·도메인·썸네일 미리보기를 최대 2개 표시합니다. 화면에 보이는 카드부터 해당 웹페이지의 Open Graph/Twitter 메타데이터를 조회합니다. 미리보기가 없거나 접근할 수 없으면 원래 링크 제목과 도메인을 유지합니다. Teams 내부 카드와 웹사이트의 최신 메타데이터가 다르면 미리보기 모양이 다를 수 있습니다.

미리보기 요청은 메시지 조회와 별도로 최대 2개씩 처리하며, 성공 결과를 1시간, 실패 결과를 5분간 메모리에서 캐싱합니다. 네이티브 캐시는 최대 48개/12MiB, 화면 캐시는 최대 48개/이미지 8MiB입니다. 웹페이지는 512KiB, 썸네일은 PNG/JPEG/GIF/WebP 1MiB 이내로 제한하고 총 조회 시간을 12초로 제한합니다. 공개 HTTP(S) 주소의 메타데이터만 조회하며, 리디렉션마다 주소를 검증하고 Teams 토큰·쿠키를 보내지 않습니다. 원문 스크립트·스타일·이벤트는 실행하지 않습니다.

### Teams 데이터 처리 구조

미확인 표시는 **이 위젯에서 확인한 시점**을 기준으로 채널 탭에 파란 점으로 표시합니다. Teams 앱의 읽음 상태와는 동기화하지 않습니다. 다른 사람이 작성한 새 글·새 댓글의 생성 시점을 비교하며, 내 메시지·반응·수정 시점은 기준에서 제외합니다. 처음 연결한 계정/채널은 첫 조회를 기준점으로 삼아 기존 대화를 모두 미확인으로 표시하지 않습니다. 이후 앱을 종료한 동안 도착한 메시지도 다음 조회에서 비교합니다.

채널 대화의 아래쪽을 표시한 상태에서 마우스를 대거나 입력창에 포커스를 두고 0.9초간 확인하면 표시를 지웁니다. 위쪽 대화를 읽거나 다른 댓글 스레드를 보고 있을 때는 채널 전체를 자동 확인 처리하지 않습니다. 확인 시점은 계정 ID와 채널 ID별로 `%APPDATA%\com.rocket.desktopcalendarwidget\teams-read-marks.json`에 저장합니다. 시점은 항상 앞으로만 이동하고 저장 실패 시 미확인 표시를 유지합니다. 사용자 ID를 조회할 수 없는 기존 연결에서는 확인 상태를 추정하지 않습니다.

| 계층 | 책임과 갱신 정책 |
| --- | --- |
| `TeamsPanel` / `Conversation` | 화면·스크롤·초안 관리. 선택한 대화는 60초마다, 전체 채널은 180초마다 최신 페이지 확인. 숨김 상태에서는 주기 조회 중단 |
| `TeamsData` | 채널/스레드/페이지별 메모리 캐시. 캐시를 즉시 표시하고 45초 이상 지난 데이터 갱신. 같은 요청 병합, 동시 조회 최대 2개 |
| 캐시 보관 | 최근 사용 순서로 최대 100페이지, 직렬화 데이터 추정 8MiB 한도. 본문과 초안은 디스크에 저장하지 않으며 재실행 후 첫 조회는 네트워크 사용 |
| 갱신·충돌 처리 | 채널은 활동 순으로 반환되는 첫 페이지를 갱신하고 기존 표시 목록과 ID로 병합. 댓글 화면은 이미 연 댓글 페이지도 갱신. 전송·반응 변경 및 계정 재연결 전의 오래된 응답은 폐기 |
| 오류·요청 제한 | 일반 조회 실패는 30초부터 최대 5분까지 지수 지연. 429 응답은 모든 채널에 Retry-After 대기 적용. 메시지 POST는 자동 재전송하지 않음 |
| Rust / Graph | OAuth 갱신을 직렬화하고 만료 120초 전까지, 최대 5분간 액세스 토큰을 메모리에서 재사용. 실제 토큰 수명 미제공 시 캐시하지 않음 |
| 네이티브 읽음 저장소 | 본문 없이 확인 시점만 별도 파일에 원자적으로 저장. 손상된 설정을 빈 값으로 덮어쓰지 않음 |

채널 목록 API는 전체 댓글 활동에 따른 수정 순으로 루트 메시지를 반환합니다([Microsoft 문서](https://learn.microsoft.com/graph/api/channel-list-messages?view=graph-rest-1.0)). 따라서 정기 갱신 때 이전 페이지 전체를 다시 읽지 않습니다. 매우 활발한 채널에서 조회 사이에 50개가 넘는 스레드가 변경되면 미확인 판정은 조회된 최신 활동 범위에 한정됩니다. 댓글 수와 댓글 생성 시점은 확장된 댓글과 그 추가 페이지를 확인하므로 댓글이 매우 많은 스레드는 첫 조회 비용이 남습니다. 더 큰 규모에서는 서버 측 변경 알림 수집과 계정별 암호화 디스크 캐시를 별도 단계로 도입할 수 있습니다.

검증: `pnpm test:teams`로 요청 병합·캐시 만료·메모리 한도·계정 전환·동시 변경·읽음 저장 실패·요청 제한을 확인하고, `cargo test --lib --target-dir D:/cargo-target`로 네이티브 저장·메시지 파싱·URL 검증을 확인합니다.

배경 투명도는 `%APPDATA%\com.rocket.desktopcalendarwidget\appearance.json`에 즉시 저장하며, 0%도 재실행 후 그대로 복원합니다. 기존 웹뷰 설정은 처음 한 번만 옮깁니다. 저장 중이거나 실패하면 설정 메뉴에 표시하며, 읽기 실패 시 기존 파일을 덮어쓰지 않습니다.

회의실 상세는 내 일정과 공유된 회의실 캘린더를 함께 조회합니다. 본인이 초대되지 않았어도 로그인 계정에 상세 읽기 권한이 있으면 주최자·본문·참석자·필수/선택 구분·응답 상태를 툴팁에 표시합니다. 회의실 사서함이 삭제한 본문이나 제공하지 않는 응답 정보는 복원하거나 추정하지 않습니다. 기존 사용자는 권한 추가 후 위젯 설정 → Outlook → 다시 연결을 한 번 진행합니다. 이후에도 403이면 Exchange의 회의실 캘린더 공유 권한을 확인합니다. 앱은 조직의 공유 권한을 변경하지 않습니다. 상세 조회가 실패해도 예약 시간표와 내 일정에서 이미 확인한 상세는 유지합니다.
